# 评分规则

每项 1–5 分，乘权重后合计（满分 100）。评委必须为每个分数写一句理由，并引用 `EVIDENCE.md` 的编号。没有证据支撑的维度最多给 2 分。

## 插件想法

| 维度 | 权重 | 5 分的样子 |
|---|---|---|
| 需求频率 | 5 | 大部分做游戏的人都会遇到，有调查比例或大量重复讨论 |
| 痛点严重度 | 4 | 导致项目放弃、发不出去、卖不动，或耗掉大量时间 |
| 数据证据强度 | 4 | 多个独立来源的定量数据 |
| 和 OhMyGame 的契合 | 3 | 正好落在 Agent 写代码 + 生成素材 + 试玩 + 发布的流程里，用户在 OhMyGame 里自然会碰到 |
| 可行性 | 2 | 用现有插件 API 就能做出有用的 MVP；缺口写清楚 |
| 差异化 | 2 | 现有插件、内置功能和外部工具没做好 |

## 游戏想法

| 维度 | 权重 | 5 分的样子 |
|---|---|---|
| 市场证据 | 5 | 同类或相邻品类近年有数据支撑的成功，且不是红海；或有明确未满足的玩家需求 |
| 差异化钩子 | 4 | 一句话说得清、能传播（适合直播、短视频、和朋友玩） |
| 适合 AI 小团队生产 | 4 | 系统驱动、美术负担低、内容可程序生成；1–3 人几周到几个月能做出可玩版 |
| 平台契合 | 3 | 适合网页 / H5 / 小游戏或小体量 Steam，单局短，链接即玩 |
| 风险 | 2 | 版权、技术、审核、获客风险低（5 分 = 风险低） |
| 能验证 OhMyGame 能力 | 2 | 做这款游戏会用到并检验 OhMyGame 的试玩、联机、素材生成、发布等能力 |

## 致命问题（任一成立直接淘汰，除非下一代修正）

- 需求或市场证据只有轶事。
- 和已有插件或内置功能重复。
- 插件：现有 API 和合理的宿主补充都做不出来。
- 游戏：核心乐趣依赖大量手工内容或高精度 3D，AI 小团队做不出来；或纯模仿某款已有游戏。
