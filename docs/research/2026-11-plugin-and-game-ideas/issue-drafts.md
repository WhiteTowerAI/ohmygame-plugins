## 草稿 1（H13）：把发布游戏的外部网络行为写成文档

**标题**：docs(publishing): 写明发布到社区的游戏能不能请求外部地址、网站会不会把网址参数传进游戏

**现状（2026-11-25、11-26 两次线上观察，不是读代码）**

- 抽查的 3 款已发布游戏，播放域 `g-<id>.ohmygame.zone` 的响应都没有 CSP，也没有 COOP、COEP、Permissions-Policy；其中一款在加载 Google Fonts。
- 网站游戏页的 iframe 是 `sandbox="allow-scripts allow-same-origin …"`，不限制网络请求。
- 打开 `https://www.ohmygame.ai/g/<slug>?pt=3`，游戏 iframe 的 `src` 带着 `?pt=3`，也就是网站会把网址参数原样传给游戏。
- `packages/server` 和 `src/daemon/publish` 里都没有设置 CSP 的代码；Cloud 的代码不在公开仓库里，没有核对。

**为什么要写下来**

- 很多游戏（外部字体、CDN 上的库、作者自己的统计）依赖"能请求外部 HTTPS 地址"，但现在这只是现状，没有任何文档保证，以后 Cloud 一加 CSP 就会无声地坏掉。
- 插件 `playtest-loop`（规划中）想让作者把试玩数据发到自己的端点，并且只在网址带 `?pt=` 时启用。它能不能做，取决于这两点是不是规则。

**希望**

1. 在 `docs/runtime.md` 的 Publishing 一节写明：发布的游戏能否请求外部地址（只允许 HTTPS？有没有限制）、网站是否会把网址参数传进游戏 iframe。
2. 说明社区条款是否允许游戏把玩家的匿名游玩数据发给作者自己的地址；如果允许，需要满足什么（告知、只在带参数时、不含个人信息）。
3. 如果以后要加 CSP，先在 changelog 里预告。

这只是写文档，代码不用改。

## 草稿 2（H1）：给作者的试玩数据：游玩漏斗和反馈

**标题**：feat(community): 让作者看到自己游戏的试玩漏斗和反馈，包括访客

**问题**

- 小团队找试玩的人难、记录难、整理反馈更难：一项网页游戏开发者调查里 60.4% 只找亲友试玩，17.4% 找不到试玩者，21.0% 做完才第一次给外人玩（Gamedev.js Survey 2025，n≈445）。CHI PLAY 2024 的访谈研究也把"招不到人、记录不下来、分析不过来"列为三大难点。
- OhMyGame 已经能把游戏发布成链接，但作者只能看到进入次数、点赞和评论，看不到玩家在哪一步离开。
- 网站游戏页上的评论要登录才能写，网页上只读；从分享链接进来的试玩者大多是访客，没有地方留反馈。
- 游戏 SDK 的访客成绩是私有的（`packages/server/src/game-data-routes.ts` 里 `public: identity.kind === "account"`），所以拿排行榜当计数器统计不到访客。

**希望（最小版本）**

1. 游戏 SDK 加一个可选的 `game.playtest.event(name, data?)`：只在作者开启"收集试玩数据"、且网址带作者生成的试玩参数时上报，事件名和数据有长度限制，不收个人信息。
2. 作者在 OhMyGame 里能看到每一轮试玩的漏斗：打开、开始、第 N 关、失败、重开、离开，以及访客和登录玩家的人数。
3. 网站游戏页允许访客留一条短反馈（可带一个评分），只有作者能看到。
4. 同意文案、保留期限（比如 90 天）、只有作者能读，写在文档和游戏页上。

**它解决什么**

- 作者不用自己搭收集端点（插件 `playtest-loop` 的过渡方案要求作者自己配 Apps Script 或 Worker）。
- 插件 `ship-ladder` 能用真实数据衡量"做完率"，而不是只看本地记录。

**不在范围内**：A/B 实验、录屏、跨游戏的玩家画像。
